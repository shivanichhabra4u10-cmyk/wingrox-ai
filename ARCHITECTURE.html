SECTION 04 · DATA FLOW

What happens when a user answers a question.

From click to durable storage in 6 steps. Total user-perceived latency: 0ms (UI is optimistic). Total time to durability: ~800ms-1.5s.

User clicks an option

In any of the 100 quantitative questions, user taps one of the answer buttons. UI button gets a gold border, ready state changes.

State updates instantly

dtAnswer1Q(qId, optIdx) fires. DT_STATE.answers[qId] = optIdx in memory. Live master score recalculates in the header.

Auto-advance after 250ms

Next question slides in. Module gating logic checks if current module is complete to enable Continue button.

Adapter queues a save

API adapter wraps dtAnswer1Q and calls wingroxSession.queueSave({answers: {[qId]: optIdx}}). Save coalesces into a single batched request after 800ms of inactivity.

PATCH request fires

PATCH /api/sessions/:id with batched answers. JWT verified. Session ownership checked. Zod validates that answer values are integers between 0 and 10.

Postgres write

Prisma merges new answers into the existing answers jsonb column. Single row update. updatedAt bumped. Response returns updated session to client (which discards it — adapter only cares about success/failure).
